# 将项目公开到 GitHub

当前目录已准备源码布局、MIT 代码许可证、贡献指南、Issue / PR 模板和 Windows CI。结构改造本身不创建远程仓库或推送文件。

## 公开前检查

1. 项目提供者已于 2026-10-20 确认 `skins/whale`、`skins/phoebe` 可随本项目公开，见各皮肤的 `LICENSE.txt` 和 `NOTICE.md`。这是提供者的确认记录，不是第三方原作者授权的独立核验，也不向其他使用者授予图片的通用再利用权。后续新增或替换素材仍须确认权利和使用范围。
2. 执行 `build.ps1 -Test`，确认离线可构建。若发布完整便携包，再按 BUILDING.md 准备依赖并构建 CPU 服务。
3. 新建 Git 仓库后检查待提交列表：应包括 `src/`、`services/`、配置、已获授权皮肤、测试、文档和 GitHub 模板；`.gitignore` 已排除 `research/`、个人输出、环境、依赖和 ZIP。若文件以前已被跟踪，需要另外移出暂存区，`.gitignore` 不会自动取消跟踪。
4. 不提交 `%LOCALAPPDATA%` 设置、设备完整实例 ID、蓝牙地址、服务备份或私有驱动。当前用于测试的迈从报文已移除机器专属路径。

## 仓库设置

在 GitHub 创建仓库并上传本地源码后，检查 Actions 的 Windows build and checks。开启 Issues，贡献者即可选择设备适配、皮肤贡献或问题反馈模板。建议默认分支只接受 PR，并要求构建检查通过；有硬件协议改动时，仍需人工核对协议依据和实机记录。

在仓库描述中说明项目只支持 Windows；在 Releases 分发经过验证的便携包，不把 `vendor/` 的二进制依赖混入源码提交。新增维护者时再填写实际负责人或 CODEOWNERS，不用占位账号。
